## 1. What the print assumes on M

- §15 standing hypotheses (p. 184, am.txt:3239): "Let M be an abelian monoid. Let X be a separated algebraic space over S endowed with an action a of A(M)_S."
- Thm 15.4 (p. 185, am.txt:3284–3292): "Assume moreover that X is finitely presented over S. Assume additionally that one of the following conditions is satisfied (i) X is affine over S, (ii) M is a group and there exists an S-affine strongly-FPR atlas for X (…), then Π(a) is a finite poset."
- Proof of (i) (am.txt:3294–3298): Prop 2.22 (grading ⟺ action, "Let S be a scheme and let X be a scheme over S such that X → S is affine", no hypothesis on M, p. 138), finite presentation ⟹ a finite set E of degrees, Thm 3.20 (p. 144, stated for the fixed abelian monoid M of §3, no finiteness), conclusion X^N = X^{⟨N∩E⟩}.
- Sections with "M finitely generated" as a standing hypothesis: §5 (p. 154, am.txt:1589, "for some finitely generated abelian group M") and §11 (p. 171). They are used only in Prop 15.5, i.e. in case (ii).

So for Thm 15.4 (i), **"M finitely generated" is a Lean addition, not a print hypothesis**; removing it is a genuine unrestriction (grade 2 → grade 1), not a no-op. For (ii) the f.g. is implicit in the print's own proof (recorded wall; untouched here).

## 2. The printed proof of 15.4 (i) for an arbitrary abelian monoid M (verified)

Hypotheses used: X → S affine, X → S finitely presented, **S quasi-compact** (needed; counterexample verified in the g5 note and its check), M any abelian monoid.

1. (Prop 2.22) X = Spec_S(A) with A = ⊕_{m∈M} A_m a quasi-coherent M-graded O_S-algebra. No condition on M.
2. (Finite degrees) S is covered by finitely many affine opens S_j = Spec R_j (S quasi-compact). On each, A(S_j) is a finitely generated R_j-algebra (finite presentation). Each of the finitely many generators is a finite sum of homogeneous components; collecting the components gives finitely many homogeneous generators with degrees in a finite set E_j ⊂ M. Put E := ⋃_j E_j, finite. No condition on M: the finiteness comes from `Finsupp.support` of the generators under the coaction, as in `exists_chart_degrees` (Sec15General.lean:634).
3. (Thm 3.20) For a magnet N, X^N is the closed subscheme cut out by the ideal J_N generated by the A_m, m ∈ M∖N.
4. (X^N = X^{⟨N∩E⟩}) Put P := ⟨N∩E⟩ ⊂ N. Then J_N ⊂ J_P (monotonicity in N). Conversely, over S_j, A_m is spanned by monomials in the homogeneous generators g_1…g_r (degrees e_i ∈ E_j ⊂ E) whose degrees sum to m. If m ∉ P, every such monomial contains some g_i with e_i ∉ P; as e_i ∈ E, this means e_i ∉ N, so g_i ∈ A_{e_i} ⊂ J_N and the monomial lies in J_N. Hence J_P ⊂ J_N locally, so J_P = J_N and X^N = X^P. Only the monoid structure of M is used (sums of degrees).
5. (Finiteness) A pure magnet N satisfies N ⊂ P = ⟨N∩E⟩ ⊂ N (Def 15.2 applied to X^N = X^P), so N = ⟨N∩E⟩ is determined by the subset N∩E of the finite set E. Hence |Π(a)| ≤ 2^{|E|}. The set of attractors {X^N} is the image of Π(a) (Thm 15.3 for X affine, any M: `pureEquivRange (attractorOrder_affine act)`), hence finite (Rem 15.6).

**Conclusion.** Thm 15.4 (i) holds for every abelian monoid M, with the single correction "S quasi-compact" (or "X quasi-compact"). This is the argument the Lean already implements; see §4.

## 3. Does `exists_gamma` need FG mathematically?

No. `exists_gamma` (Sec5Etale.lean:775) produces the coaction γ : Γ(U_T) → Γ(U_T)[M] from the action of the universal point of A(M) on the tautological point of U over Spec Γ(U_T)[M], via `exists_ptOf` (Sec3Rest.lean:594). The only place M enters is the site membership `contains_M hA : B.Contains (Spec Γ(U_T)[M])` (lines 781–783, 785–789), whose proof (line 759–762) is `AddMonoidAlgebra.finiteType_of_fg R' M` + `contains_ft`. Degrees: `exists_chart_degrees` takes the finite union of the `Finsupp.support`s of γ(g) for the finitely many generators g; finite for any M. `[AddCommGroup M]` is used only to type `jr`, `eM`, `mapR` (lines 729–744), which are `AddMonoidAlgebra.singleZeroRingHom`, `single`, `mapRingHom`: they need `[AddMonoid M]` only. Confirmation inside the repo: Prop337General.lean section `Rings` (line 71–) redefines `jr`, `eM`, `mapR`, `inclR`, `ρN`, `monN` for `(M : Type u) [AddCommMonoid M]` and they typecheck there.

So FG serves **site membership only**: Spec R'[M] must have size below the cutoff of the big fppf site. The replacement is a cardinality bound.

## 4. The size lemma — it already exists

`AlgMag.P337.contains_alg` (Prop337General.lean:49–67):

```
lemma contains_alg {R P : Type u} [CommRing R] [AddCommMonoid P] (hP : #P < B.cutoff)
    (hR : B.Contains (Spec (.of R))) : B.Contains (Spec (.of (AddMonoidAlgebra R P)))
```

Proof read: `#R[P] ≤ #(P →₀ R) ≤ #(Finset (P × R))`, then `mk_finset_of_infinite`, `mk_prod`, `mul_lt_of_lt` with `B.aleph0_lt_cutoff`; it goes through `P337.contains_iff : B.Contains (Spec (.of R)) ↔ #R < B.cutoff` (line 38). This is exactly "#R'[M] ≤ max(#R', #M, ℵ₀) < cutoff". The same file (lines 212–220) already has, under `variable [hM : Fact (#M < B.cutoff)]`,

```
lemma contains_any (T) [IsAffine ((Sch).obj T)] (N : AddSubmonoid M) :
    B.Contains (Spec (.of (AddMonoidAlgebra (RT T) N))) :=
  contains_alg ((mk_subtype_le _).trans_lt hM.out) (contains_RT T)
lemma contains_M {R'} [CommRing R'] (h : B.Contains (Spec (.of R'))) :
    B.Contains (Spec (.of (AddMonoidAlgebra R' M))) := contains_alg hM.out h
```

i.e. the monoid versions of the two FG lemmas of Sec5Etale.lean (`contains_any` :1662, `contains_M` :759), with the same names and signatures.

Mathlib alternatives (not needed, for the record): `AddMonoidAlgebra.cardinalMk_of_infinite : #R[M] = max #R #M` (`[Infinite M] [Nontrivial R]`), `cardinalMk_eq_lift_of_fintype`, in `Mathlib/Algebra/MonoidAlgebra/Cardinal.lean`; `MvPolynomial.cardinalMk_le_max : #(MvPolynomial σ R) ≤ #R ⊔ #σ ⊔ ℵ₀`; repo: `card_finiteType` (ChartQSLocalEtale.lean:20, `#R ≤ max ℵ₀ #C` for a finite type C-algebra).

**Choice of hypothesis.** `[Fact (#M < B.cutoff)]` (the Prop337General convention) rather than `hM : B.Contains (Spec (ZMon M))` (the `thm153_general` convention, FinalNonQCLocal.lean:121). They are equivalent given `hZ : B.Contains (⊤_ Scheme)`: `Contains (Spec ℤ[M]) ⟹ #ℤ[M] < cutoff` (`contains_iff`) `⟹ #M < cutoff` (m ↦ single m 1 is injective, `Finsupp.single_left_injective one_ne_zero`), and conversely `contains_alg` with R = ULift ℤ. `#M < cutoff` is the primitive: it is implied by the existence in the site of any Spec R'[M] with R' ≠ 0, so it is forced by the objects the statement talks about. Grade 1 harmless: the cutoff of the site is a free parameter, chosen above #M.

**Import direction.** Prop337General imports Sec8Limits → Sec8Theorem83 → Sec5Etale. So Sec5Etale cannot use `P337.contains_alg`; `contains_iff` and `contains_alg` (30 lines, no dependency beyond `Scheme.size_of_isAffine`, `Finsupp.graph_injective`, `mk_finset_of_infinite`) move upstream into Sec5Etale section `Generic` (before line 719), and Prop337General keeps the names as `alias`es or deletes its copies. Sec15General imports Sec5Etale directly (line 5), so it sees them.
